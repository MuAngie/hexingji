## 2. 产品背景

### 2.1 项目来源

「禾迹」的灵感来源于十个勤天所传递出的精神：扎根土地、真实劳动、关注农业、支持地方发展。

在这一精神影响下，许多粉丝开始把喜欢转化为真实行动：前往不同地点，购买当地农产品，参与线下活动，帮助传播地方故事，整理攻略，或者通过线上方式支持当地发展。

这些行为真实存在，但目前分散在微博、小红书、抖音、朋友圈、群聊和个人相册中，缺少一个专门的产品，把“大家共同走过哪里”和“我自己做过什么”分别记录下来。

### 2.2 当前问题

当前存在几个明显问题：

1. 群体行动分散，用户无法快速看见大家曾经共同支持过哪些地点。
2. 地点的参与情况缺少统一数字，用户不知道一个地方有多少人去过、帮助过或持续参与过。
3. 个人行动散落在相册、备忘录和社交平台里，难以形成长期、有仪式感的个人记录。
4. 传统社区产品过度依赖发帖、评论、点赞和关注，容易增加表达压力，也会让产品偏离“行动记录”的核心。
5. 用户并不一定想公开自己的行程、身份和详细经历，但仍希望自己的参与被计入群体行动。

### 2.3 产品机会

「禾迹」可以用“沉浸式地图 + 单向参与按钮 + 私密足迹本”的方式，建立一个边界清晰的行动记录产品。

产品重点不是建立复杂社交关系，而是解决两件事：

- 让用户看见群体共同走过和支持过的地方。
- 让用户用私密、纸面感的方式记录自己的行动轨迹。

## 3. 产品定位

### 3.1 一句话定位

「禾迹」是一个以沉浸式地图为入口的粉丝助农行动记录产品。用户可以在公开地图上看见大家参与过哪些地方，也可以把自己的参与自动记录进私密的「禾的足迹本」。

### 3.2 核心表达

> 把喜欢种进土地，把行动留成足迹。

### 3.3 核心产品结构

- 公开空间：群体行动地图。
- 公开轻互动：点击“我也参与了！”。
- 私密空间：禾的足迹本。
- 产品关系：公开地图负责“看见大家”，足迹本负责“记录自己”。

### 3.4 产品原则

1. 公开地图只展示群体数字，不展示具体参与者身份。
2. “我也参与了！”是单向、轻量、低压力的交互。
3. 用户点击后不需要填写表单，不跳转，不打断地图浏览。
4. 每次有效参与都会自动在「禾的足迹本」生成一条私密记录。
5. 个人内容默认仅本人可见，不对外开放。
6. 第一版不建立评论、点赞、关注和动态关系。
7. 地点参与允许重复，但同一账号同一地点需要满足时间间隔。

## 4. 产品目标

### 4.1 Demo 阶段目标

第一版 Demo 需要验证以下核心判断：

1. 用户是否能快速理解“地图是群体行动入口”。
2. 用户是否愿意通过一次点击表达“我也参与了”。
3. 用户是否能理解地点上的数字代表群体持续参与，而非单次打卡热度。
4. 用户是否愿意在个人页面继续整理和补充自己的私密足迹。
5. 手账、日记、纸面感的个人记录方式是否与产品气质匹配。

### 4.2 MVP 目标

第一版 MVP 需要跑通以下链路：

> 进入地图 → 浏览地点 → 点击地点 → 查看地点卡片 → 点击“我也参与了！” → 地点公开数据更新 → 自动生成私密足迹记录 → 用户之后在「禾的足迹本」中补充和编辑。

### 4.3 非目标

第一版不以以下内容为目标：

- 建立公开内容社区。
- 激励用户持续发帖。
- 建立粉丝关系链。
- 进行电商交易。
- 提供真实 GIS 导航。
- 提供完整地点审核和后台管理。

## 5. 目标用户与使用场景

### 5.1 浏览型用户

用户目的：想看看大家去过哪里、支持过哪些地点。

主要行为：

- 打开地图。
- 拖动和缩放地图。
- 按类型筛选地点。
- 点击地点标注。
- 查看地点故事和群体参与数据。

### 5.2 轻参与用户

用户目的：曾经参与过某个地点，希望留下一个低成本的群体信号。

主要行为：

- 点击地点卡片中的“我也参与了！”。
- 看到地点参与次数增加。
- 不填写表单。
- 不公开身份。
- 不进入社交互动。

### 5.3 私密记录用户

用户目的：想长期记录自己跟着大家去过哪里、做过什么。

主要行为：

- 有效参与后，系统自动生成一条私密记录。
- 进入「禾的足迹本」查看。
- 补充具体行动、日期、文字和图片。
- 按时间、地点或类型回顾。
- 编辑或删除个人记录。

## 7. 核心产品逻辑

### 7.1 公开行动地图

地图是产品首页，也是用户进入产品后的第一体验。地图展示多个被支持过的地点，每个地点拥有地点名称、地点分类、地点故事、去重参与人数、累计参与次数、最近群体行动摘要、地图坐标与参与状态。

地图不展示参与者名单，不展示谁刚刚点击，也不形成公开个人轨迹。

### 7.2 单向地点参与

#### 按钮文案

> 我也参与了！

#### 参与含义

用户点击该按钮，表示自己曾经以某种方式参与、支持或帮助过这个地方。参与可以包括到访现场、购买农产品、参与志愿活动、帮助传播或线上支持。第一版不要求用户选择具体类型。

#### 点击后的系统行为

1. 校验该本地身份上次参与该地点的时间。
2. 若已超过冷却期，则判定为有效参与。
3. 当前地点累计参与次数 +1。
4. 若该身份此前从未参与该地点，则去重参与人数 +1。
5. 自动生成一条私密足迹记录。
6. 按钮进入冷却状态。
7. 地图标注出现一次轻微发光动画。
8. 页面显示轻提示，但不跳转。

#### 默认冷却期

默认冷却期为 30 天。同一身份可以在同一地点重复参与，但两次有效参与之间至少间隔 30 天。

#### 冷却期内再次点击

若用户在 30 天内再次点击同一地点：

- 不增加参与次数。
- 不增加参与人数。
- 不生成新的足迹记录。
- 显示提示：“你最近已经参与过这里，可以在冷却期结束后再次记录。”

#### 公开数字

地点同时维护两种数字：

- 去重参与人数：有多少不同身份参与过。
- 累计参与次数：所有有效参与记录总数。

推荐地点卡片文案：

> 218 位同行者参与过  
> 累计留下 326 次参与记录

#### 参与后的按钮状态

冷却期内显示“已参与”或“已留下禾迹”，按钮不可再次点击。

#### 页面反馈

有效参与后出现轻提示：

> 这次参与，已经写进禾的足迹本。

不自动跳转，不弹出表单。

### 7.3 自动生成私密足迹

每次有效参与后，系统自动在「禾的足迹本」中创建一条记录。

默认文案格式：

> 2026 年 7 月 10 日，参与了青山麦田集市的行动。

每次冷却期结束后的新参与，都生成一条新记录，不覆盖历史记录。

### 7.4 禾的足迹本

「禾的足迹本」是用户的私密个人页面，不是公开主页。它负责记录用户跟着大家去过哪里、参与过什么、支持过哪些地点，以及之后想补充什么。个人记录默认只保存在本地，不向其他用户展示。

## 9. 页面需求

### 9.1 行动地图页

页面占满视口，地图为主视觉，其他信息通过悬浮卡片覆盖在地图上。地图支持鼠标拖动、滚轮缩放和触控双指缩放，初始居中。具体技术方案后续单独讨论。

左上显示品牌“禾迹”和标语“把每一次奔赴，种进真实的土地里。”顶部中间显示静态卡片：

> 禾迹行动地图  
> 128 个地点 · 3,426 次参与记录 · 8,912 位同行者

底部中间设置筛选栏：

- 全部
- 助农购买
- 志愿服务
- 地方攻略
- 线下行动
- 线上支持

右上设置“禾的足迹本”入口。右下建议设置放大、缩小和重置视角按钮。

### 9.2 地点详情弹卡

点击地点标注后弹出卡片，展示地点名称、标签、地点故事、去重参与人数、累计参与次数、最近群体行动与“我也参与了！”按钮。

有效参与后，数字即时更新，按钮变为已参与状态，地点标注发光一次，自动创建足迹记录，并显示轻提示。点击地图空白处、关闭按钮或其他地点可关闭或替换卡片。

### 9.3 禾的足迹本页

页面顶部显示：

> 禾的足迹本  
> 记录我跟着大家的脚步，去过哪里、做过什么。  
> 仅自己可见

视觉方向为手账、日记与纸面感。建议使用米白纸张背景、纸张边缘、日期印章、胶带、页签、票据式地点标签和手绘路线。

推荐三栏布局：

- 左侧：全部记录、待补充、已编辑、按地点、按时间。
- 中间：按日期倒序的手账式记录卡片。
- 右侧：已参与地点数、累计有效参与次数、待补充记录数、最近参与时间和足迹小地图。

移动端改为单栏布局。

### 9.4 足迹记录卡片

自动生成状态示例：

> 2026 年 7 月 10 日，参与了青山麦田集市的行动。

展示“自动记录”“待补充”“仅自己可见”标签，并提供编辑、删除和查看地点操作。

用户可在后续编辑中补充日期、行动类型、自定义标题、正文、图片和心情标签。编辑后状态变为“已编辑”。

删除记录只删除私密内容，不减少地点公开参与次数或去重参与人数。

### 12.2 冷却期判断

```ts
const COOLDOWN_DAYS = 30;

function canParticipate(
  placeId: string,
  localUserId: string,
  records: ParticipationRecord[]
): boolean {
  const latestRecord = records
    .filter(
      record =>
        record.placeId === placeId &&
        record.localUserId === localUserId
    )
    .sort(
      (a, b) =>
        new Date(b.participatedAt).getTime() -
        new Date(a.participatedAt).getTime()
    )[0];

  if (!latestRecord) return true;

  const lastTime = new Date(latestRecord.participatedAt).getTime();
  const now = Date.now();
  const cooldownMs = COOLDOWN_DAYS * 24 * 60 * 60 * 1000;

  return now - lastTime >= cooldownMs;
}
```

### 12.3 首次参与判断

```ts
function isFirstParticipation(
  placeId: string,
  localUserId: string,
  records: ParticipationRecord[]
): boolean {
  return !records.some(
    record =>
      record.placeId === placeId &&
      record.localUserId === localUserId
  );
}
```

### 12.4 有效参与更新逻辑

```ts
function participate(placeId: string) {
  if (!canParticipate(placeId, localUserId, participationRecords)) {
    showCooldownMessage();
    return;
  }

  const firstTime = isFirstParticipation(
    placeId,
    localUserId,
    participationRecords
  );

  updatePlaceStats(placeId, {
    participationCountDelta: 1,
    uniqueParticipantCountDelta: firstTime ? 1 : 0
  });

  const participationRecord = createParticipationRecord(placeId);

  createAutoFootprintEntry({
    placeId,
    participationRecordId: participationRecord.id
  });

  persistAll();
  showSuccessFeedback();
}
```

## 14. 视觉与体验要求

地图页面关键词：沉浸式、可探索、温暖农业、轻游戏化、插画感、悬浮卡片、木牌式地点标签、柔和发光。不要做成真实 GIS、电商页面或普通社区信息流。

建议色彩：米白、禾苗绿、麦穗黄、浅棕和少量天空蓝。

「禾的足迹本」关键词：手账、日记、纸面感、私密、温暖、长期记录。可以使用纸张纹理、打孔装订、胶带、日期印章、页签、票据式地点标签和手绘路线。

建议动效：

- 地点 Hover 轻微放大。
- 选中地点高亮。
- 有效参与后 marker 发光一次。
- 参与数字平滑递增。
- 地点卡片 fade + scale。
- 足迹记录新增时出现纸张滑入效果。
- 不使用强烈粒子或庆祝动画。

## 16. 验收标准

### 16.1 地图页面

- 页面打开后第一视觉是地图。
- 地图可拖动和缩放。
- 地点标注可点击。
- 地点筛选可用。
- 顶部静态卡片不随地图移动。
- 点击空白区域可关闭地点卡片。
- 页面中不出现公开信息流。

### 16.2 参与逻辑

- 点击“我也参与了！”后，累计参与次数 +1。
- 首次参与时，去重参与人数 +1。
- 非首次但超过冷却期时，只增加累计参与次数。
- 冷却期内重复点击不增加数字。
- 冷却期内不生成足迹记录。
- 有效参与后自动生成足迹记录。
- 有效参与后不自动跳转。
- 页面刷新后参与状态保留。

### 16.3 禾的足迹本

- 自动生成的记录可以看到。
- 记录默认仅自己可见。
- 记录按日期倒序。
- 记录可编辑和删除。
- 删除私密记录不影响公开地点数据。
- 页面具有明显纸面感和手账感。
- 页面中不出现点赞、评论、粉丝和关注。

### 16.4 本地存储

- localUserId 能生成并保留。
- 参与记录刷新后保留。
- 足迹记录刷新后保留。
- 地点数字刷新后保留。
- 冷却期判断在刷新后仍有效。

## 17. 风险与边界

### 17.1 “参与”含义模糊

第一版不强迫用户分类，以降低门槛。产品说明中明确：到访、购买、志愿、传播和线上支持都可视为参与。后续可在足迹本编辑时补充具体类型。

### 17.2 本地存储不等于真实账号

清除浏览器数据、更换设备或浏览器后，本地身份会丢失。Demo 阶段接受该限制，真实版本需接账号系统和服务端校验。

### 17.3 公开数字真实性

第一版数字为 Mock 与本地模拟，不对外宣称为真实统计。

### 17.4 自动记录可能积累过多

提供“待补充”筛选与删除功能。后续可增加归档、批量整理或同日记录合并。

### 17.5 产品被做成普通社区

第一版明确禁止评论、点赞、关注、动态流和公开个人主页。公开互动仅限地点参与数字。

## 20. 当前版本成功标准

第一版成功需要满足：

1. 用户一眼理解这是一个可探索的群体行动地图。
2. 用户可以用一次点击表达“我也参与了”。
3. 用户不需要填写表单，也不会被迫公开自己。
4. 地点同时展示去重参与人数和累计参与次数。
5. 同一身份可以周期性重复参与同一地点。
6. 每次有效参与都会自动形成一条私密足迹。
7. 用户可以之后回到「禾的足迹本」补充记录。
8. 公开地图和私密记录之间边界清晰。
9. 产品没有滑向普通社交社区。
10. 页面视觉体现地图探索感与纸面手账感。

## 21. 核心总结

「禾迹」第一版的核心不是做一个热闹的社区，而是建立一条清晰、克制的产品链路：

> 大家在地图上共同留下参与数字，我在自己的足迹本里安静地留下个人记忆。

公开地图负责记录群体，单向按钮负责降低参与门槛，「禾的足迹本」负责承载个人长期记录。

用户点击“我也参与了！”时，不需要解释、不需要发帖、不需要表演。数字增加，地图被点亮，同时一条私密日记自动写入足迹本。用户可以当下离开，也可以以后回来补充。

这就是「禾迹」V0.1 最重要的产品体验。
