## 1. 接入目标与信息归属

Excel 负责维护事实内容，网页负责把项目、人物关系和参与入口组织成可浏览、可筛选的视图。以项目编号串联信息，不再依靠在一个单元格内追加长段落。

当前工作簿包含 14 个项目、68 条人物／群体关系、33 条参与记录和 18 条待核验事项。这是本次版本的基线数量，后续新增时不能把这些数量写死在网页中。

| 工作表 | 网页数据集合 | 一行的含义 | 唯一编号 |
| --- | --- | --- | --- |
| 项目汇总 | `projects` | 一个项目 | `HJ-001` 等项目编号 |
| 项目人物 | `projectPeople` | 一个对象与一个项目的关系 | `PR-001` 等关系编号 |
| 参与方式 | `participationOptions` | 一个可单独维护的入口或参与线索 | `PA-001` 等参与编号 |
| 待核验 | `verificationTasks` | 一项核验任务，可以关联多个项目 | `T-001` 等待办编号 |

关联方式：

```text
projects.id ← projectPeople.projectId
projects.id ← participationOptions.projectId
projects.id ← verificationTasks.projectIds[]
```

“项目人物”包括个人、群体、团队、组织。68 条记录不是 68 位独立自然人。桑杰多吉在墨脱农业与背夫故事中分别有关系记录，符合当前设计；不得仅凭同名把记录合并。当前没有独立的全局人物档案，也没有已核实的人物—渠道关联字段，前端不能自动推断某家店归属于某个人。

## 4. Excel 导入约定

工作簿位置：

```text
D:\L\Codex Space\same world\outputs\heji-maintenance-20261031\禾伙人助农公益地图_分表维护版_v1.xlsx
```

四张表均在第 6 行放置表头，第 7 行开始存储记录。现有 Excel Table 名为 `Projects`、`People`、`Participation`、`Pending`。

导入时优先按工作表名和表头定位字段。表头文字是字段约定，不依赖固定列字母；未来插入新列时，原字段仍应正确映射。检查表格末尾以外是否出现有编号的数据行，若有则提示扩展表格范围，防止新增内容被漏读。

空值与日期处理：

- 全空行跳过；有内容但没有唯一编号的行报告具体工作表和行号，不静默丢弃。
- 空文本和仅空白字符统一为 `null`；保留正文内部换行，以便分段展示。
- 空坐标保持 `null`，不转换成 `0`，也不从前一行填充。
- 日期统一导出为 `YYYY-MM-DD` 或 `null`。识别 Excel 日期对象／序列值，并遵循工作簿的日期系统，避免时区换算导致日期前移一天。
- “线索补充日期”“最后核验日期”“文件导出时间”分别存储。导出文件不代表当天重新核验全部记录。
- Excel 的关联项目名称和汇总计数是公式结果，可能存在缓存过期；前端以项目编号重新关联名称，以明细重新统计。
- 正文以纯文本显示，换行可使用 `white-space: pre-wrap`；不要把资料内容当作可执行 HTML。

## 6. 状态如何影响网页

### 信息依据与记录保留

核验枚举：`原表线索`、`用户提供`、`公开资料核实`、`待核验`、`有冲突`。

这些值表示记录的依据，不能单独用于判断“今天能否购买／报名”。“用户提供”也不能自动改写成“官方认证”。默认展示在册记录，已归档记录在编辑端和历史视图保留。

### 参与入口的有效状态

| 状态 | 展示建议 | 行动按钮 |
| --- | --- | --- |
| 待确认 | 保留线索并标明开放情况待确认 | 有合适链接则“查看渠道信息”；无链接则展示名称及可复制搜索词 |
| 可参与 | 显示类别、平台、步骤、核验依据及日期 | 有链接可“查看参与入口”；购买／报名措辞还需确认目标确为相应入口 |
| 季节性开放 | 展示季节与当前安排 | 查看活动信息，不自动宣称当前正在报名 |
| 暂时关闭 | 展示暂停提示 | 保留说明，停止直接购买／报名引导 |
| 已结束 | 作为历史内容呈现 | 展示历史信息，不显示当前参与按钮 |

若核验状态为“有冲突”，编辑端突出冲突；公开端不显示强行动按钮。纯文化传播、关注账号、产业观察类记录，不使用“立即购买”等标签。

**当前 33 条参与记录的有效状态均为“待确认”**，反映本次整理没有重新检查全部入口。页面应显示“有 33 条参与线索，开放情况待确认”，不要让统计为 0 的“已确认可参与”变成“没有任何参与方式”。

## 7. 地图和项目详情如何组织

### 地图视图

- 每个项目保留一个项目节点，人物和渠道作为详情内容，不为每条店铺记录新增地图点。
- 项目浮层展示项目名、地点、简短问题、在册对象数及参与记录数；完整叙述放在详情中。
- 缺少坐标的项目保留在侧边列表，提供“位置待补充”筛选，不让它从数据中消失。
- 墨脱农业与背夫故事使用相同县级锚点时，保留现有节点展开／显示偏移机制；不要更改真实经纬度来避让图标。
- 县级、乡镇级、区域示意坐标要显示精度说明，不能当成农户家址、店铺门址或导航终点。

### 坐标与现有示意点

当前网页给西双版纳水果、云南橡胶设置了区域示意坐标，而工作簿中相应项目没有精确数字坐标。迁移后以工作簿原始坐标为事实字段；确需延续示意点时，另存 `displayCoordinates`、`isIllustrative: true` 和说明，不能回填为已核实坐标。

现有插画地图通过 `latLngToMapPosition` 接受具名 `latitude`／`longitude`。若以后对接其他地图服务，应按该服务要求适配顺序与坐标系；当前表没有独立坐标系字段，不能把坐标系视作已经核验。缺失坐标时，现有 `.toFixed(5)` 调用也需要增加空值分支。

### 项目详情

建议按以下顺序展示：

1. **项目概况**：项目名、地点、节目节点、问题。
2. **行动与进展**：十个勤天做了什么、当前状态与后续结果。
3. **当地有什么**：地方产品、产业和文化内容；为空则不展示空区块。
4. **人物与群体**：按关系记录生成卡片，显示名称、对象类型、身份、核验状态。
5. **参与方式**：按参与类别分组，一条入口一张卡片，显示产品、平台、步骤和有效状态。
6. **文案与来源**：金句文案、来源链接、原核验口径。编辑原创文案保留标记，不能套成受访者直接引语。

暂时兼容旧组件时，可以在适配器里用在册记录生成 `focusTargets` 和 `participation` 摘要；摘要只用于显示，不写回 Excel，不成为第二套可编辑数据。

建议采用“左侧项目列表，右侧项目工作区”，可复用现有详情抽屉布局。

| 工作区 | 主要内容 | 操作 |
| --- | --- | --- |

第一版实用筛选：项目、对象类型、参与类别、平台、核验状态、有效状态、是否有链接、是否已归档。搜索可覆盖项目名、人物称呼、店铺名和产品文本。点击人物／渠道搜索结果，应进入所属项目并定位相应记录。

公共浏览页面默认隐藏内部“下一步”等编辑工作文字，编辑界面完整显示。当前项目没有人物照片、店铺图标或联系人电话字段，缺失时用文字卡片即可，不自动补造内容。

保存行为必须说清楚：

- **第一阶段建议：Excel 为主数据。** 编辑工作簿，重新导出 JSON，检查变更预览，确认后构建并更新网站。前端暂作浏览和筛选。
- **需要浏览器整理草稿时：** 本地表单修改只保存在当前草稿中，明确标注“未写回主表”；提供带版本号的结构化导出供合并。浏览器刷新或换设备的行为需明确说明。
- **需要网页直接保存时：** 再增加持久化服务、身份权限、变更记录和冲突处理。现有静态网页部署不会自动把修改写回 `D:\...` 的 Excel 文件。
- 不同时启用互不知情的 Excel 与网页双向覆盖。先确定主数据归属，再实现另一端的导入／导出。

## 9. JSON 结构与读取示例

```typescript
function getProjectView(data: HejiContent, projectId: string) {
  const project = data.projects.find(item => item.id === projectId);
  if (!project) return null;

  const people = data.projectPeople.filter(
    item => item.projectId === projectId && item.recordStatus === "在册"
  );
  const options = data.participationOptions.filter(
    item => item.projectId === projectId && item.recordStatus === "在册"
  );
  const tasks = data.verificationTasks.filter(
    item => item.projectIds.includes(projectId)
  );

  return {
    project,
    people,
    options,
    tasks,
    counts: {
      objects: people.length,
      participationRecords: options.length,
      available: options.filter(item => item.availabilityStatus === "可参与").length
    }
  };
}
```

这与 Excel 当前汇总口径一致；“可参与”计数不是公开强按钮数量，按钮仍需检查信息依据、链接类型和参与类别。数据量增长后可按 `projectId` 建索引，不必提前引入复杂状态管理。

## 10. 当前表缺少的网页展示字段

旧 `HejiLocation` 还要求 `mapLabel`、`nodeType`、`compactOffset`、`impactStatus`、项目级 `verificationStatus`、`lastVerified` 等字段。新版工作簿没有将它们全部独立成列。

建议在展示配置中显式保留已有的地图短名、类别和偏移，并用第 3 节映射关联。对新增项目，缺失配置要提示补充，不套用上一条项目。

事实核验相关字段不能依靠默认值补齐：

- 项目历史“已核验”不能传递给该项目所有人物与渠道。
- 项目进展正文与入口“可参与”是不同字段。
- 无明确项目级核验日期时允许为空，详情展示原核验口径，不硬塞导出日期。
- 新内容与旧正文冲突时，以新版工作簿为内容输入，同时提示人工复核；不静默从旧网页补回已删除段落。
- 当前表头“金句文案”可能包含编辑拟写内容；有歧义时按普通文案呈现，不添加名人署名。

## 11. 导入检查和交付验收

正式导入器应先生成问题清单与变更预览，再替换网页数据文件。

**阻止覆盖的错误：** 缺少必要工作表／字段、重复唯一编号、人物或渠道关联不存在的项目、任务中出现未知非空项目编号、非空坐标无法解析或超出经纬度合法范围、枚举值不在约定范围、必填编号／名称为空。

**允许保留但提示补充：** 没有精确坐标、没有链接、没有最后核验日期、群体未具名、候选任务无项目编号、只提供店铺搜索词。这些本来就是可维护的信息状态。

建议验收场景：

1. 为东北助农新增一条参与记录，只增加 HJ-006 的记录数与详情卡片。
